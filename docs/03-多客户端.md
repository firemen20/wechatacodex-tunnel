# 多客户端兼容

## 一、五种客户端，三种格式

| 客户端 | 内核 | 用哪个文件 |
|---|---|---|
| **Clash Meta / FlClash** | mihomo | `ClashMeta-FlClash.yaml` |
| **v2rayng** | Xray | `通用订阅-base64.txt` |
| **Nekoray** | sing-box / Xray | `通用订阅-base64.txt` 或 `Hiddify-Nekoray-singbox.json` |
| **Hiddify** | sing-box | 同上 |
| 手动导入 | — | `节点链接.txt` |

**最通用的是 base64 订阅** —— v2rayng / Nekoray / Hiddify 都能吃。

---

## 二、不要假设"所有客户端能力相同"

| 能力 | mihomo | sing-box | Xray |
|---|---|---|---|
| VLESS + WS | ✅ | ✅ | ✅ |
| Trojan + WS | ✅ | ✅ | ✅ |
| **链式代理**（`dialer-proxy` / `detour`） | ✅ | ✅ `detour` | ❌ **不支持** |
| Hysteria2 | ✅ | ✅ | ❌ |

**关键结论**：任何依赖 `dialer-proxy` 的方案（比如"用购买的节点当入口"），**v2rayng 表达不了**。
要么给不同客户端不同的方案，要么统一用不依赖链式的方式（本项目就走这条路）。

## 三、生成

```bash
# 一次生成全部格式
node tools/optimize-ips.js --top 3

# 或只生成订阅格式（已有 Clash 配置时）
node tools/build-subscription.js dist/clash-nodes.yaml dist
```

产物：

```
dist/
├── ClashMeta-FlClash.yaml          Clash Meta / FlClash
├── 通用订阅-base64.txt              v2rayng / Nekoray / Hiddify
├── Hiddify-Nekoray-singbox.json    Hiddify / Nekoray
└── 节点链接.txt                     手动逐条导入
```

---

## 四、导入方式

**Clash Meta / FlClash**
配置 → 从文件导入 → 选 `ClashMeta-FlClash.yaml`

**v2rayng / Nekoray / Hiddify**
订阅 → 从剪贴板/文件导入 → 粘贴 `通用订阅-base64.txt` 的内容

**Nekoray / Hiddify（sing-box 配置）**
配置 → 导入 sing-box 配置 → 选 `Hiddify-Nekoray-singbox.json`

**手动**
打开 `节点链接.txt`，逐条复制 `vless://...`

### 局域网分发（可选）

想让路由器或其它设备通过 URL 订阅，可以起一个本地 HTTP 服务：

```bash
node tools/proxy-start.js   # 见脚本内说明
```

⚠️ **注意**：绑定到局域网 IP 意味着同网段任何设备都能下载到配置 —— **而配置里的 UUID 就是节点密码**。只在你信任的网络里这么做。

## 五、为什么一定要做"往返校验"

生成是一回事，**客户端解析回来是不是同一个节点**是另一回事。字段名写错、编码错、少一个参数，肉眼看不出来，到了客户端就是连不上。

```bash
node tools/verify-roundtrip.js dist
```

它做三件事：

| 检查 | 说明 |
|---|---|
| base64 订阅 → 解码 → 逐条解析 → **逐字段比对** | 验证链接格式没错 |
| sing-box JSON → 逐字段比对 + 策略组引用完整性 | 验证 JSON 结构没错 |
| Clash YAML → 交内核 `-t` 做语法/语义校验 | 验证 YAML 能被真正解析 |

**踩过的坑**：第一版校验脚本用 `server:port` 做节点键，但多个 Worker 共用同一批 IP:端口，导致拿 A 的节点去比 B 的，误报 9 处不一致。
**键必须带上 Host（或 UUID）。**

## 六、sing-box 配置的版本兼容

sing-box 1.12~1.14 有几个**破坏性变更**，写 JSON 时必须注意：

| 报错 | 原因 | 修法 |
|---|---|---|
| `legacy DNS server formats are deprecated in 1.12.0 and removed in 1.14.0` | 旧的 `{address: "https://..."}` 被删了 | 改 `{type: "https", server: "1.1.1.1"}` |
| `missing route.default_domain_resolver … will be removed in 1.14.0` | 1.12+ 要求显式指定解析器 | 加 `route.default_domain_resolver: {server: "dns-remote"}` |
| `detour to an empty direct outbound makes no sense` | DNS 服务器不能显式 detour 到 direct | 去掉该 `detour`（直连本就是默认） |
| `independent_cache is deprecated` | 1.14 弃用 | 去掉 |

**建议**：生成后用 `sing-box check -c config.json` 校验（本项目的模板已按 1.14 的写法适配）。

### 关于"能不能实跑验证"

sing-box 的 **Android 构建需要以 VPN 应用身份运行** —— 普通 App 直接跑会：

```
FATAL start service: subscribe route updates: permission denied
```

（Android 禁止普通 App 使用 netlink 套接字，换 musl 静态构建也一样。）

**所以本地只能做到 `check` 通过，实跑要在真实客户端里验证。** 这是环境限制，不是配置问题。
