# 踩坑记录

> 这里每一条都是实际踩过、有证据的。按"坑"的顺序排列，不是理论。

---

## 1. 子域名能不能当 CF zone，取决于公共后缀列表 ⭐

**现象**：`node1.abc.freedomain.cn` 加进 Cloudflare 报错：

```
Please ensure you are providing the root domain and not any subdomains
```

**原因**：Cloudflare 的判断依据是**公共后缀列表（PSL）**。
- `freedomain.cn` **不在 PSL** → 它是"某个根域名的子域"，CF 拒绝
- `github.io` **在 PSL** → `node1.myname.github.io` 就算可注册根域名，CF 接受

**判断方法**：
```bash
curl -s https://publicsuffix.org/list/public_suffix_list.dat | grep -x "你的后缀"
```

**教训**：注册免费域名前，先确认**上级域在不在 PSL**。

## 2. 顺序不能反：先建 zone，再改 NS

**现象**：先去注册商改了 NS，再去 CF 建 zone —— 白改。

**原因**：**必须先在 Cloudflare 建 zone，CF 才会分配给你 2 个 NS**。
在那之前你手上根本没有"正确的 NS 值"可填。

```
❌ 改 NS → 建 zone
✅ 建 zone（拿到真实 NS）→ 改 NS
```

---

## 3. NS 值必须来自 CF 页面，不能凭空写

**现象**：示例里写了 `xxxx.ns.cloudflare.com` / `yyyy.ns.cloudflare.com`，被当成真值填进去了。

实测这两个主机名**根本不存在**：
```
xxx.ns.cloudflare.com   → NOERROR 但无 A 记录（不存在）
yyyy.ns.cloudflare.com  → 同上
dana.ns.cloudflare.com  → 173.245.58.105 ✅（真实的 CF NS 长这样）
```

**教训**：真实的 CF NS 是 `celeste` / `harlan` / `dana` / `rob` 这类**有意义的单词**。
**必须从 CF 建 zone 后显示的页面原样抄。**

### 附：怎么诊断 NS 填错

公共 DoH 只会返回 `SERVFAIL`，看不出原因。**要直接问权威服务器**：

```bash
node tools/dns-query.js 你的域名 NS a.ns.<上级的NS服务器>
```
返回 AUTHORITY 段里能看到上级到底委派给了谁。

## 4. Custom Domains 端点权限受限 → 改用 Workers Route

**现象**：用账户级 token 调 `POST /accounts/{id}/workers/domains` 报：

```
10405  Method not allowed for this authentication scheme
```

**解法**（效果一样）：
1. 建一条 **proxied 的 A 记录**（内容随意，比如 `192.0.2.1`，Worker 会接管请求）
2. 建 **Workers Route**：`node1.example.com/*` → `你的worker名`

## 5. 上传 Worker 模块的两个硬性要求

**现象**：`PUT /accounts/{id}/workers/scripts/{name}` 报：

```
Uncaught SyntaxError: Unexpected token 'export'
```

明明代码里 `export default` 是合法的 ES module 语法，为什么报错？

**两个原因，都要满足**：

| 原因 | 修法 |
|---|---|
| **Content-Type 不对** | 模块必须用 `application/javascript+module`，用 `application/javascript` 会被当成普通脚本 |
| **文件带 BOM** | 源码开头有 `ef bb bf` 时部署失败，要先剥掉 |

完整的上传方式：
```bash
curl -X PUT \
  -F "metadata=@meta.json;type=application/json" \
  -F "worker.js=@code.js;type=application/javascript+module;filename=worker.js" \
  "https://api.cloudflare.com/client/v4/accounts/$ACC/workers/scripts/$NAME"
```

且 `metadata.main_module` 必须与表单字段名一致（都是 `worker.js`）。

## 6. 小心清空绑定：`bindings: []` 是地雷

有工具类脚本上传 Worker 时写死了 `bindings: []` —— 这会**清空 Worker 的环境变量**（`UUID`、`PROXYIP`），节点直接废掉。

**部署前务必确认**：要么显式带上原绑定，要么先 `GET .../settings` 把绑定读出来。

## 7. `/sdcard` 是 noexec（Android 特有）

**现象**：把 mihomo 放到 `/sdcard/...` 后执行报 `Permission denied`。

**原因**：Android 的 `/sdcard` 是 FUSE 挂载，**默认 noexec**。

**解法**：内核放到应用私有目录（如 `/data/data/<pkg>/files/`），用 `--core <路径>` 指定。

## 8. 明文路径会被"应用层干扰"

**现象**：某些时段，明文方案下**持续传输被压到 0**，短请求偶尔成功：

```
第1轮: gstatic 204/0.89s   google 000/5.01s   youtube 000/5.01s
吞吐: 0.00 MB/s
```

**对照实验**（同一时刻）：

| 路径 | 结果 |
|---|---|
| 链式加密443 | ✅ 3.67 MB/s |
| 直连互联网 | ✅ 正常 |
| **明文直连 CF IP** | ❌ 0.00 MB/s |

**已排除的原因**：
- ❌ TCP 层封锁 —— 2052/80/8080/443 都能 connect 成功
- ❌ `?ed=2048` 早期数据 —— A/B 对照（带 ed vs 纯 `/`）都是 0
- ❌ 节点自身坏了 —— 同批节点走 443 TLS 完全正常
- ❌ CF 额度耗尽 —— Worker 响应正常

**结论**：这是**对明文流量的应用层干扰**，随时段波动（同一份配置白天 10.31 MB/s，深夜 0）。

**这就是推荐自定义域名（TLS 443）的原因。**

---

## 9. `?ed=2048` 早期数据不背这个锅

排查时怀疑过 WS 的 early-data 参数 `?ed=2048` 被识别。做了 A/B：

| 路径 | 成功 |
|---|---|
| `/?ed=2048` | 0/3 |
| `/` | 1/3 |

**两者都失败** → 不是 ed 的问题。别再花时间在这上面。

## 10. 自测时的自环陷阱

**现象**：通过 `worker-A` 的节点去请求 `worker-A` 自己的域名 → 拿到无关页面。

**原因**：Worker 会去拨自己，**死循环**。

**教训**：测试 Worker 是否可达时，**要用不同的 Worker/域名**，或者用一个不含伪装逻辑的精简 Worker 来验证链路。

---

## 11. 交叉测量要交错轮次

优选时如果"先把 A 测 10 次、再测 B 10 次"，会把**时间漂移**误当成 A/B 差异。

正确做法：`A B B A A B ...` 交错进行，再比中位数。

实测教训：单次测量得出过"负载均衡快 3.7 倍"的结论，交错复测后发现是噪声，已撤回。

---

## 12. shell 里解析 URL 别用 `%%:*`

`${url%%:*}` 会在 `https://` 的第一个冒号处断开，得到 `https`。用 `|` 之类不冲突的分隔符。

---

## 13. 循环里调用 curl 会吃掉 stdin

```bash
while read -r line; do curl ...; done < file   # ❌ curl 消费了 stdin
```
加 `</dev/null`，或先把文件读进数组。

## 14. 免费节点聚合这条路的坑（已放弃）

早期版本做过"抓免费公共订阅 → 聚合 → 优选"。设计参数：

```js
const CACHE_TTL = 1800;        // 30 分钟
const VERIFIED_TTL_HOURS = 2;
```

依据是实测：**快照生成 25 分钟后只剩 40%~55% 节点可用**。

**结论：这条路走不通** —— 衰减太快，维护成本远高于收益。
自建 Worker 之后，"外部节点衰减"这个问题从根上消失了。

---

## 15. 别把"改名"和"加主机名"搞混

给 Worker 绑自定义域名时，**Worker 名字不变**，只是多了一个主机名指向它。旧配置里引用的 `*.workers.dev` 依然有效。
